# Claude Meter — GNOME Shell extension

Monitors Claude usage from the GNOME top bar. Full spec: `plan.md` (Italian).

## Stack
- GNOME Shell 50 (Fedora 44, Wayland), GJS 1.88, **ES modules only** (`import ... from 'gi://Gio'`, `resource:///org/gnome/shell/...`). No `imports.*` legacy syntax.
- UUID: `claude-meter@grillofra`. GSettings schema id: `org.gnome.shell.extensions.claude-meter`.
- No external dependencies. No GTK in shell-side code (only `prefs.js` and `prefs/` may use Gtk4/Adw).
- UI in **Italian and English**: every user-visible string goes through `t()`/`tn()` of `lib/i18n.js` (no hardcoded UI text, no gettext: it cannot force a language per extension). Product/brand names (Claude Meter, Claude Code, Clawd, Anthropic) are not translated. Code comments, logs, `UsageError` messages, schema descriptions and shell scripts are in English.

## Hard rules
- Never block the shell: all file and network I/O must be async (`Gio._promisify` + `*_async` methods, Soup 3 `send_and_read_async`). No `GLib.file_get_contents`, no sync `load_contents`, no `spawn_sync`.
- Never log tokens, credentials, prompts or message content. `console.debug` of counts/errors only.
- Never invent numbers: if data is missing, return/show `null` and let the UI show "—". Only exception: a plan window with no live value (never fetched, or past its `resetsAt`) is shown as 0% (usage restarts from zero after a reset).
- Cache tokens (`cache_creation_input_tokens`, `cache_read_input_tokens`) are NOT input tokens.
- Each module only touches its own files (see "File ownership").

## Crab sprites
Animations come from PNG spritesheets in `clawd-animation/` (committed but dev-only: not packaged by `build.sh`; old versions live in git history, no `old/` subfolders) + manifest `animations.json` (fps, `pixel`, `maxHeight` px, loop, seconds, state mapping). The build script is a CLI (`check`, `install` default, `list`, `preview`, `add`, `remove`, `set-state`): it prints the height limit (floor(maxHeight/pixel) rows, today 26 px = 13 rows), a per-animation report, and refuses to write anything if an animation is too tall. `gjs -m tools/build-animations.js` (run manually by the developer when animations change, NOT by `build.sh`) crops them to a common grid, builds one palette and writes the committed `lib/sprites.js` (`FPS`, `PIXEL`, `MAX_HEIGHT`, `SPRITE_HEIGHT`, `GRID_W`, `GRID_H`, `PALETTE`, `STATES`, `ANIMATIONS`); `lib/crabs.js` compiles it into per-colour layers and runs the per-session state machine (`CrabRow`). Requirements: 16×16 frames in horizontal strips, same size for every sheet, content within 13 rows (rows 2..14), ≤ 62 colours. Update flow: edit PNGs (or `generate.py`) → `check` → `install` → `gjs -m tests/test-crabs.js` → commit sheets + manifest + `lib/sprites.js`. Format and full guide: see `SPRITES.md` (keep it in sync).

### lib/i18n.js

Pure module (GLib only). Each process has its own current language: `extension.js` (shell) and `prefs/window.js` (prefs) set it from the `language` key and follow `changed::language`. Dictionaries: `lib/locale/{common,panel,prefs,errors}.js`, each `{it: {...}, en: {...}}`, keys `<area>.<section>.<name>`; `tests/test-i18n.js` enforces same keys, same placeholders, same kind (string/plural) in both languages and unique keys across areas. `lib/format.js` outputs in the current language (signatures unchanged; weekday/month names from `Intl.DateTimeFormat(getLocale())`, Italian 'lun'/'nov', English 'Mon'/'Nov', 24 h clock in both). Live switch: the indicator relabels its menu (no rebuild, top bar and crabs untouched); extension.js re-sends the error currently shown, translated; prefs rebuild both pages keeping the visible one.

### lib/planScheduler.js
Pure plan-refresh policy used by extension.js (which keeps state, timers and I/O): constants (`PLAN_STALE_ON_OPEN_MS`, `PLAN_MIN_SPACING_MS`, `PLAN_TICK_TOLERANCE_MS`, `RATE_LIMIT_BASE_MS`, `RATE_LIMIT_MAX_MS`, `RESET_FETCH_DELAY_S`, `REASON_PRIORITY`), `isPlanDue(reason, now, {backoffUntil, lastAttempt, lastSuccess, intervalS, usage})`, `resetTimes(usage)`, `planExpired(usage, now)`, `mergeReason(pending, reason)`, `backoffDelay(hits, retryAfterMs)`, `nextResetFetchDelayS(usage, now)` (null when no future reset, capped at 3600).

### lib/sessionStore.js
```js
export class SessionStore {
    constructor(claudeDir = ~/.claude, procDir = '/proc')   // procDir is injectable for tests
    async list(cancellable = null)            // -> Promise<Session[]>, most recently used first
    async getDeletionTargets(session, cancellable = null) // -> Promise<Target[]>, only existing paths
    async trash(session, cancellable = null)  // -> Promise<{ trashed: string[], failed: [{path, message}] }>
                                              // throws Error with .code === 'active' (nothing trashed)
    async getDeletionTargetsFor(sessions, cancellable = null) // -> Promise<Target[]>, rule evaluated on the set
    async trashMany(sessions, cancellable = null)
        // -> Promise<{ trashed: string[], failed: [{path, message}], skippedActive: Session[], trashedBytes: number }>
        // invalid session -> throws, nothing trashed; active ones skipped, the rest trashed
    async getProjectDeletionTargets(projectDir, cancellable = null) // -> Promise<Target[]>
    async trashProject(projectDir, cancellable = null) // -> Promise<{ trashed, failed }>
                                              // throws Error with .code === 'active' (nothing trashed)
    async getTargetsSize(targets, cancellable = null) // -> Promise<number> bytes, recursive, symlinks not followed, missing ignored
    async _trashPath(path, cancellable)       // the only call to Gio trash_async; tests override it
// trash/trashMany/trashProject results also carry trashedBytes = size of the targets actually trashed
// (measured just before trashing each one; failed ones excluded).
}
// Session = { sessionId: string, title: string|null, projectPath: string|null,
//             projectDir: string, file: string,
//             createdAt: Date|null, lastUsedAt: Date|null, active: boolean,
//             size: number|null /* bytes of the .jsonl */ }
// Target  = { path: string, kind: 'conversation' | 'session-dir' | 'file-history'
//                               | 'session-env' | 'todos' | 'project-dir' }
```
Pure module (Gio/GLib only). A conversation is a first-level `projects/<project>/<sessionId>.jsonl`. Title = last `custom-title`/`ai-title` record, else first real user message (slash-command wrappers skipped), else `null`. Active = `sessionId` listed in `~/.claude/sessions/<pid>.json` with a live `/proc/<pid>` (file mtime is not considered). Linked data: `projects/<project>/<sessionId>/`, `file-history/<sessionId>/`, `session-env/<sessionId>/`, `todos/<sessionId>*`. When the project directory would be left empty or with only `memory/`, the single `project-dir` target replaces `conversation` and `session-dir`; for several sessions this rule is evaluated on the whole set per project (one shared helper, also used by `getDeletionTargets`), so selecting every conversation of a project yields one `project-dir`. `trashMany` re-checks activity and recomputes targets on the non-active ones, so a skipped conversation keeps its project dir. `projectDir` for the project methods must be a direct child of `projects/` (as in `Session.projectDir`); the dir is re-read at call time (session ids = first-level `*.jsonl` names) and the targets are `project-dir` (everything, incl. `memory/`) + linked data of every session; `trashProject` refuses the whole project if any session is active.

Preferences code: `prefs.js` only calls `fillWindow(window, settings)` of `prefs/window.js` (testable from plain gjs with an in-memory GSettings backend); `prefs/generalPage.js` (`buildGeneralPage`), `prefs/sessionsPage.js` (`SessionsPage`), `prefs/widgets.js` (`SignalTracker`, `bindComboRow`, `clearInitialSpinFocus`, `setClickable`, `setClickableDescendants`), `prefs/languageSelector.js` (`createLanguageComboRow`). Pointer cursor (`setClickable`) on everything that reacts to a click: switch/combo rows, the −/+ buttons of spin rows (not their text), the tab switchers, checkboxes, rows in deletion mode, bar/retry buttons, the confirmation dialog buttons (set after `choose()` presents it); the default arrow while insensitive (own or inherited, via `state-flags-changed`). Window: no search button; tabs "Preferenze" (icon `claude-meter-brush-symbolic`) and "Conversazioni" (`claude-meter-chat-symbolic`), symbolic SVGs from `icons/` added to the icon theme by `fillWindow` (`iconsDir`); no custom header title (Adw.PreferencesWindow has no bar above the tabs). Language: an `Adw.ComboRow` "Lingua" (values "Italiano" / "English", never translated) as the first row of Aspetto; it shows the effective language and writes `language`; on change both pages are rebuilt (page-level `SignalTracker` disconnected, sessions overlay uninstalled and reinstalled) keeping the visible page. Preferences: the general page "Claude Meter" shows the groups in this order (one `page.add` loop in `buildGeneralPage`): Aspetto, Soglie colori, Barra superiore, Aggiornamento. "Conversazioni" page (`SessionsPage` in `prefs/sessionsPage.js`): one `Adw.PreferencesGroup` per project (title = last folder of the project path, '~' for the home dir; the tildified full path is the tooltip of the group's title label), one row per conversation. There is no header group and no reload/trash-mode button: the first group is untitled and only shown for the loading / empty / error states; the list reloads every time the page becomes visible (`notify::visible-page`, skipped while busy or in deletion mode). The only way into deletion mode is checking a checkbox. Row subtitle: `Ultima apertura <date> · <size of the .jsonl>` (`GLib.format_size`, "—" if unknown). Every row has a `Gtk.CheckButton` as suffix and every project header a tri-state "seleziona tutte" `Gtk.CheckButton` (selects the non-active conversations; insensitive with tooltip "Tutte le conversazioni sono in corso" when all are active). Outside the mode the checkboxes are invisible but keep their space (`opacity` 0, not `visible=false`) and show on pointer hover (`Gtk.EventControllerMotion` on the row / on the group header box) or keyboard focus (`notify::has-focus`); checking any of them enters the mode with that selection. Active ("In corso") rows have an insensitive checkbox with tooltip. The project check has `margin_end: 14` so it lines up with the row checks. In deletion mode all checkboxes are visible, clicking a row toggles it, and a floating icon-only bar appears centered at the bottom of the window: [← `go-previous-symbolic`, flat, tooltip "Annulla"] [destructive trash button, tooltip "Elimina le conversazioni selezionate", insensitive with nothing selected]; no count and no size (the size is shown only in the confirmation dialog). Stock look: `.toolbar` class (6 px padding and spacing) plus the libadwaita popover surface (`--popover-bg-color`, 15 px radius, 1 px border, popover shadow; opaque, unlike `.osd`), buttons with the stock Adwaita radius (no `circular`/`pill`). `Adw.PreferencesWindow` accepts only `PreferencesPage` children, so `SessionsPage.installOverlay()` wraps the window content (the Adw.ToastOverlay) in a `Gtk.Overlay` and adds the bar as overlay; the bar is shown only while the mode is on and the Conversazioni page is visible (`notify::visible-page`), and the last project group gets a 72 px bottom margin meanwhile. Unchecking the last selected conversation (row or project check) leaves the mode; otherwise only the back button, Esc (capture-phase key controller, present only while the mode is on), reload or a completed deletion do. There is no per-row or per-project trash button: every deletion (one conversation, a selection, a whole project) goes through `getDeletionTargetsFor` + `_confirmAndTrash` + `trashMany` (one `Adw.AlertDialog` listing the target paths plus "Verranno spostati nel cestino X in totale" from `getTargetsSize`, memory/ warning when a `project-dir` target appears, which the set rule produces when a project is fully selected; final toast "N conversazioni spostate nel cestino: X" from `trashedBytes`); `trashProject` is not used by the UI. Page controls are insensitive while an operation runs; the selection is cleared on exit, reload or after a deletion. Deletion is always a move to the system trash; `history.jsonl`, `shell-snapshots/`, `paste-cache/`, `telemetry/`, `jobs/`, `daemon/` are never touched. Tests must never call the real `trash_async`.

### Settings keys (gschema)
- `refresh-interval` (u, default 60, range 30..3600) seconds
- `warn-threshold` (i, default 70, 1..100) percent → yellow
- `critical-threshold` (i, default 90, 1..100) percent → red
- `plan-refresh-interval` (u, default 300, range 60..3600) seconds — Anthropic usage endpoint (rate-limited)
- `bar-color-mode` (s, 'accent' | 'traffic', default 'accent') — menu bars and top-bar rings
- `panel-show-five-hour`, `panel-show-seven-day` (b, default true) — top-bar rings
- `crabs-enabled` (b, default true), `crab-max` (u, default 3, 1..10) — number of sessions with a crab; the rest are counted in "+N"
- `crab-overflow` (s, 'overflow' | 'crop', default 'overflow') — what to do when the panel is shorter than the sprites; its prefs row ("Animazioni troppo alte") is insensitive with an explanatory tooltip when the measured space is enough. Prefs call the crabs "Clawds"
- `panel-content-height` (u, default 0 = not measured) — written by the extension, read by install.sh
- `panel-empty` (s, 'crab' | 'icon', default 'crab') — what the top bar shows when no session crab is shown: a sleeping crab next to the rings or the icon. With `crabs-enabled` false the icon is always used: the prefs row is muted, shows "Icona" with a tooltip, and the saved value is kept for when Clawds are re-enabled
- `language` (s, '' | 'it' | 'en', default '') — UI language; '' = never chosen (resolved from the desktop language, see `resolveLanguage`)

## Verification
- Pure modules (parser, usage, data, sessions, session-store, crabs, format, i18n, scheduler) can be run outside the shell: `gjs -m tests/test-<name>.js`; `bash tests/run-all.sh` runs every test plus the schema check.
- Shell-only modules (`lib/indicator.js`, `lib/ui/*.js`, `extension.js`) cannot be imported outside GNOME Shell: test them with `dev/nested.sh` (headless isolated shell: start / eval / shot / log / stop). `lib/format.js` must stay pure (no shell imports) so it can be tested with gjs.
- Tests must use temp dirs/fixtures (`GLib.dir_make_tmp`), never write into `~/.claude` or `~/.local/share/claude-meter`. Test files print `PASS`/`FAIL` lines and exit non-zero on failure.
- Schema: `glib-compile-schemas --strict --dry-run schemas/`.

## GNOME 50 gotchas (verified in nested shell)
- `St.BoxLayout` has no `spacing` property → use CSS `spacing: 8px`. Use `orientation: Clutter.Orientation.VERTICAL`, not `vertical: true`.
- CSS `opacity` on containers is unreliable → set `actor.opacity` from code.
- Theme variants: GNOME Shell loads `stylesheet-dark.css` / `stylesheet-light.css` and reloads on color-scheme change. They are generated by `build.sh` from `styles/` (never edit the generated files). System accent color in CSS: `-st-accent-color`.
- Custom CSS properties can be read from code with `themeNode.lookup_color('-name', false)` (used by the chart `St.DrawingArea`).
- Soup 3: use `message.status_code`, NOT `get_status()` — it throws for codes missing from the `Soup.Status` enum (e.g. 429).
- The usage endpoint returns 429 when polled too often: plan polling is separate (5 min default, 60 s staleness on menu open) with exponential back-off honouring `Retry-After`. A window past its `resetsAt` is shown as 0% with "Reset avvenuto" (old percent no longer true) and extension.js fetches again `RESET_FETCH_DELAY_S` after the reset (back-off still honoured).
- The panel button hands its child the full 32 px, not the 26 px theme content box: crabs are shifted with `translation_y` (margins cannot be negative, and a child larger than its parent is clamped). The highlight box copies the stock technique (full height, 3 px transparent border, `inset 0 0 0 100px` box-shadow as background, horizontal padding = vertical gap 5 px): do NOT inset it with margins set from code, St's 150 ms transition paints the full-height box during the fade. Stock highlight = inset `box-shadow` on `#panel .panel-button:hover/:focus/:active/:checked`.
- Never size a child actor from its parent's allocation (`notify::width` + `set_size`): if the value changes while the menu is not allocated the fill ends up wrong (bar at 2% with "40%" written). Menu bars are `St.DrawingArea` like the rings, colors from custom CSS properties (`-claude-meter-bar-*`).

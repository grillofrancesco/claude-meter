# Claude Meter — GNOME Shell extension

Monitors Claude usage from the GNOME top bar. Full spec: `plan.md` (Italian).

## Stack
- GNOME Shell 50 (Fedora 44, Wayland), GJS 1.88, **ES modules only** (`import ... from 'gi://Gio'`, `resource:///org/gnome/shell/...`). No `imports.*` legacy syntax.
- UUID: `claude-meter@grillofra`. GSettings schema id: `org.gnome.shell.extensions.claude-meter`.
- No external dependencies. No GTK in shell-side code (only `prefs.js` may use Gtk4/Adw).
- UI strings in **Italian**, hardcoded (no gettext in v1).

## Hard rules
- Never block the shell: all file and network I/O must be async (`Gio._promisify` + `*_async` methods, Soup 3 `send_and_read_async`). No `GLib.file_get_contents`, no sync `load_contents`, no `spawn_sync`.
- Never log tokens, credentials, prompts or message content. `console.debug` of counts/errors only.
- Never invent numbers: if data is missing, return/show `null` and let the UI show "—".
- Cache tokens (`cache_creation_input_tokens`, `cache_read_input_tokens`) are NOT input tokens.
- Each module only touches its own files (see "File ownership").

## Crab sprites
Animations come from PNG spritesheets in `clawd-animation/` (dev-only, git-ignored: users never need it) + manifest `animations.json` (fps, `pixel`, `maxHeight` px, loop, seconds, state mapping). The build script is a CLI (`check`, `install` default, `list`, `preview`, `add`, `remove`, `set-state`): it prints the height limit (floor(maxHeight/pixel) rows, today 26 px = 13 rows), a per-animation report, and refuses to write anything if an animation is too tall. `gjs -m tools/build-animations.js` (run manually by the developer when animations change, NOT by `build.sh`) crops them to a common grid, builds one palette and writes the committed `lib/sprites.js` (`FPS`, `PIXEL`, `MAX_HEIGHT`, `SPRITE_HEIGHT`, `GRID_W`, `GRID_H`, `PALETTE`, `STATES`, `ANIMATIONS`); `lib/crabs.js` compiles it into per-colour layers and runs the per-session state machine (`CrabRow`). Format and how to add/edit animations: see `SPRITES.md` (keep it in sync).

## Interface contracts (do not change signatures)

### lib/tokenParser.js
```js
export class TokenParser {
    constructor(projectsDir = GLib.build_filenamev([GLib.get_home_dir(), '.claude', 'projects']))
    // state = { files: { [absPath]: { offset: number, size: number } }, seen: { [key]: 'YYYY-MM-DD' } }
    // state is owned/persisted by DataManager; scan() mutates it in place.
    async scan(state, cancellable = null) // -> Promise<Record[]>, only NEW records since last scan
}
// Record = { key: string, timestamp: number /*ms epoch*/, sessionId: string|null,
//            input: number, output: number, cacheCreation: number, cacheRead: number }
```
Raw JSONL facts: one JSON object per line. Usage records have `message.usage` with `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`; also top-level `timestamp` (ISO), `requestId`, `sessionId`, and `message.id`. The SAME (message.id, requestId) appears on several lines with identical usage → count once, key = `${message.id}:${requestId}`. Files live in `projects/<project>/*.jsonl` and `projects/<project>/<session>/subagents/*.jsonl` (scan recursively).

### lib/dataManager.js
```js
export class DataManager {
    constructor(statePath = GLib.get_user_data_dir()/claude-meter/state.json)
    async load()                 // missing/corrupt file -> fresh empty state, never throws
    get parserState()            // -> { files, seen } object passed to TokenParser.scan
    addRecords(records)          // aggregate by LOCAL day 'YYYY-MM-DD' from record.timestamp
    prune(now = new Date())      // drop days and seen entries older than 30 days
    async save()                 // atomic write, file mode 0600, dir created if missing
    getToday()                   // -> { input, output, total }
    getHistory(days = 30)        // -> [{ date: 'YYYY-MM-DD', input, output, total }], newest first, zero-filled
    getPlan()                    // -> { usage: PlanUsage|null, backoffUntil: ms, rateLimitHits }  (persisted)
    setPlan({usage?, backoffUntil?, rateLimitHits?})  // usage null/absent = unchanged
}
```

### lib/sessionStore.js
```js
export class SessionStore {
    constructor(claudeDir = ~/.claude, procDir = '/proc')   // procDir is injectable for tests
    async list(cancellable = null)            // -> Promise<Session[]>, most recently used first
    async getDeletionTargets(session, cancellable = null) // -> Promise<Target[]>, only existing paths
    async trash(session, cancellable = null)  // -> Promise<{ trashed: string[], failed: [{path, message}] }>
                                              // throws Error with .code === 'active' (nothing trashed)
    async getDeletionTargetsFor(sessions, cancellable = null) // -> Promise<Target[]>, rule evaluated on the set
    async trashMany(sessions, cancellable = null)
        // -> Promise<{ trashed: string[], failed: [{path, message}], skippedActive: Session[] }>
        // invalid session -> throws, nothing trashed; active ones skipped, the rest trashed
    async getProjectDeletionTargets(projectDir, cancellable = null) // -> Promise<Target[]>
    async trashProject(projectDir, cancellable = null) // -> Promise<{ trashed, failed }>
                                              // throws Error with .code === 'active' (nothing trashed)
    async _trashPath(path, cancellable)       // the only call to Gio trash_async; tests override it
}
// Session = { sessionId: string, title: string|null, projectPath: string|null,
//             projectDir: string, file: string,
//             createdAt: Date|null, lastUsedAt: Date|null, active: boolean }
// Target  = { path: string, kind: 'conversation' | 'session-dir' | 'file-history'
//                               | 'session-env' | 'todos' | 'project-dir' }
```
Pure module (Gio/GLib only). A conversation is a first-level `projects/<project>/<sessionId>.jsonl`. Title = last `custom-title`/`ai-title` record, else first real user message (slash-command wrappers skipped), else `null`. Active = `sessionId` listed in `~/.claude/sessions/<pid>.json` with a live `/proc/<pid>` (file mtime is not considered). Linked data: `projects/<project>/<sessionId>/`, `file-history/<sessionId>/`, `session-env/<sessionId>/`, `todos/<sessionId>*`. When the project directory would be left empty or with only `memory/`, the single `project-dir` target replaces `conversation` and `session-dir`; for several sessions this rule is evaluated on the whole set per project (one shared helper, also used by `getDeletionTargets`), so selecting every conversation of a project yields one `project-dir`. `trashMany` re-checks activity and recomputes targets on the non-active ones, so a skipped conversation keeps its project dir. `projectDir` for the project methods must be a direct child of `projects/` (as in `Session.projectDir`); the dir is re-read at call time (session ids = first-level `*.jsonl` names) and the targets are `project-dir` (everything, incl. `memory/`) + linked data of every session; `trashProject` refuses the whole project if any session is active.

Preferences "Conversazioni" page (`SessionsPage` in `prefs.js`): one `Adw.PreferencesGroup` per project, one row per conversation. The first group header has a flat icon-only trash button ("Elimina conversazioni") next to reload; it enters deletion mode. Every row has a `Gtk.CheckButton` as suffix and every project header a tri-state "seleziona tutte" `Gtk.CheckButton` (selects the non-active conversations; insensitive with tooltip "Tutte le conversazioni sono in corso" when all are active). Outside the mode the checkboxes are invisible but keep their space (`opacity` 0, not `visible=false`) and show on pointer hover (`Gtk.EventControllerMotion` on the row / on the group header box) or keyboard focus (`notify::has-focus`); checking any of them enters the mode with that selection. Active ("In corso") rows have an insensitive checkbox with tooltip. In deletion mode all checkboxes are visible, clicking a row toggles it, and the trash button is replaced by a destructive "Elimina (N)" (disabled at N = 0) plus "Annulla"; deselecting everything does not leave the mode, only Annulla, Esc (capture-phase key controller, present only while the mode is on), reload or a completed deletion do (`Adw.PreferencesWindow` accepts only `PreferencesPage` children, so no bottom action bar). There is no per-row or per-project trash button: every deletion (one conversation, a selection, a whole project) goes through `getDeletionTargetsFor` + `_confirmAndTrash` + `trashMany` (one `Adw.AlertDialog` listing the target paths, memory/ warning when a `project-dir` target appears, which the set rule produces when a project is fully selected); `trashProject` is not used by the UI. Page controls are insensitive while an operation runs; the selection is cleared on exit, reload or after a deletion. Deletion is always a move to the system trash; `history.jsonl`, `shell-snapshots/`, `paste-cache/`, `telemetry/`, `jobs/`, `daemon/` are never touched. Tests must never call the real `trash_async`.

### lib/indicator.js
```js
export const ClaudeMeterIndicator = GObject.registerClass({
    Signals: { 'refresh-requested': {} },
}, class ClaudeMeterIndicator extends PanelMenu.Button {
    _init(extension)    // extension: Extension instance (extension.path, extension.getSettings())
    setPlanUsage(usage /*PlanUsage|null*/, error /*string|null*/)   // keeps last value if usage null
    setTokens(today /*{input,output,total}|null*/, error /*string|null*/)
    setHistory(history /*getHistory() result*/)
    setPlanRetryAt(date /*Date|null*/)  // next plan attempt after a 429

// Crabs = first `crab-max` sessions (if `crabs-enabled`), the rest counted in "+N"; widths from the pure

// colours, bottom-aligned. Per crab: sleep (idle loop) → busy: start (laptop_out, once) → work (random

// complete; new crabs start directly in sleep/work. No session crab and no "+N": `panel-empty` 'crab' =
// one sleeping placeholder crab (PLACEHOLDER_ID), adopted by the first session that opens and taken
// back by slot 0 when the last one closes; 'icon' = the icon. 8 fps timer only while animating.
// Panel space: the button measures its theme content box (allocation − borders, 26 px on stock GNOME 50)

// Hover/focus/menu-open highlight is only on the `claude-meter-highlight` box (rings/icon): the button's own

// Emits 'refresh-requested' when the menu is opened (no manual refresh button).
// Menu = two PopupMenuSection "pages": main (plan + age) and details (tokens, 7-day chart, prefs);
// NavItem overrides activate() so switching page does not close the menu.
// Only the 5-hour and 7-day bars are drawn: PlanUsage.scoped stays in the data contract but is not shown.
// Main page item "Gestisci conversazioni": sets `prefs-start-page` to 'sessions', then opens the

```

### lib/sessionMonitor.js
```js
export class SessionMonitor {
    constructor(sessionsDir = ~/.claude/sessions, procDir = '/proc')
    async scan(cancellable = null) // -> Promise<[{ id, busy, startedAt }]>, oldest first
}
```
Claude Code writes `~/.claude/sessions/<pid>.json` with `kind` ('interactive'|'bg'), `status` ('idle'|'busy'), `procStart` (= field 22 of /proc/<pid>/stat). Only interactive sessions whose pid is alive with the same start time count. extension.js watches the directory (FileMonitor, 250 ms debounce) + polls every 5 s; nothing runs when `crabs-enabled` is false.

### Settings keys (gschema)
- `refresh-interval` (u, default 60, range 30..3600) seconds
- `warn-threshold` (i, default 70, 1..100) percent → yellow
- `critical-threshold` (i, default 90, 1..100) percent → red
- `plan-refresh-interval` (u, default 300, range 60..3600) seconds — Anthropic usage endpoint (rate-limited)
- `bar-color-mode` (s, 'accent' | 'traffic', default 'accent') — menu bars and top-bar rings
- `panel-show-five-hour`, `panel-show-seven-day` (b, default true) — top-bar rings
- `crabs-enabled` (b, default true), `crab-max` (u, default 3, 1..10) — number of sessions with a crab; the rest are counted in "+N"
- `crab-overflow` (s, 'overflow' | 'crop', default 'overflow') — what to do when the panel is shorter than the sprites; its prefs row ("Animazioni troppo alte") is insensitive with an explanatory tooltip when the measured space is enough. Prefs call the crabs "Clawds"
- `panel-content-height` (u, default 0 = not measured) — written by the extension, read by install.sh
- `panel-empty` (s, 'crab' | 'icon', default 'crab') — what the top bar shows when no session crab is shown: a sleeping crab next to the rings or the icon
- `prefs-start-page` (s, 'general' | 'sessions', default 'general') — one-shot: page to show when the preferences open; `prefs.js` consumes it and resets it to 'general' (also while the window is already open)

## Verification
- Pure modules (parser, usage, data, sessions, session-store, crabs) can be run outside the shell: `gjs -m tests/test-<name>.js`.
- Shell-only modules (`lib/indicator.js`, `extension.js`) cannot be imported outside GNOME Shell: test them with `dev/nested.sh` (headless isolated shell: start / eval / shot / log / stop). `lib/format.js` must stay pure (no shell imports) so it can be tested with gjs.
- Tests must use temp dirs/fixtures (`GLib.dir_make_tmp`), never write into `~/.claude` or `~/.local/share/claude-meter`. Test files print `PASS`/`FAIL` lines and exit non-zero on failure.
- Schema: `glib-compile-schemas --strict --dry-run schemas/`.

## GNOME 50 gotchas (verified in nested shell)
- `St.BoxLayout` has no `spacing` property → use CSS `spacing: 8px`. Use `orientation: Clutter.Orientation.VERTICAL`, not `vertical: true`.
- CSS `opacity` on containers is unreliable → set `actor.opacity` from code.
- Theme variants: GNOME Shell loads `stylesheet-dark.css` / `stylesheet-light.css` and reloads on color-scheme change. They are generated by `build.sh` from `styles/` (never edit the generated files). System accent color in CSS: `-st-accent-color`.
- Custom CSS properties can be read from code with `themeNode.lookup_color('-name', false)` (used by the chart `St.DrawingArea`).
- Soup 3: use `message.status_code`, NOT `get_status()` — it throws for codes missing from the `Soup.Status` enum (e.g. 429).
- The usage endpoint returns 429 when polled too often: plan polling is separate (5 min default, 60 s staleness on menu open) with exponential back-off honouring `Retry-After`. A window past its `resetsAt` is shown as "—" (old percent no longer true) and extension.js fetches again `RESET_FETCH_DELAY_S` after the reset (back-off still honoured).
- The panel button hands its child the full 32 px, not the 26 px theme content box: crabs are shifted with `translation_y` (margins cannot be negative, and a child larger than its parent is clamped). The highlight box copies the stock technique (full height, 3 px transparent border, `inset 0 0 0 100px` box-shadow as background, horizontal padding = vertical gap 5 px): do NOT inset it with margins set from code, St's 150 ms transition paints the full-height box during the fade. Stock highlight = inset `box-shadow` on `#panel .panel-button:hover/:focus/:active/:checked`.
- Never size a child actor from its parent's allocation (`notify::width` + `set_size`): if the value changes while the menu is not allocated the fill ends up wrong (bar at 2% with "40%" written). Menu bars are `St.DrawingArea` like the rings, colors from custom CSS properties (`-claude-meter-bar-*`).
